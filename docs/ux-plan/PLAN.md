# План улучшения UI/UX бота «Подарки не отдарки»

Итог совместной работы Claude и Codex (2026-11-04). Статус: ✅ в проде, 🔄 PR открыт, ⏳ не начато.
Это план по анализу исходников, а не результат ручной проверки в клиентах Telegram.

**Цель:** новый владелец и новый гость проходят путь «создать список → добавить подарок → отправить другу → друг открыл →
забронировал → нашёл свою бронь → снял её» без подсказок. При этом ничего не утекает и ничего не ломается.

## Этап 3. После проверки основного пути

- Скрыть чужой список из «Списков друзей» (отдельно от отказа от доступа и с учётом активных броней).

## Решения пользователя

1. Приватность — как сейчас: другие гости видят имя бронирующего под спойлером; владелец видит, что подарок занят, но не кем. Тексты карточки и `/help` говорят это прямо.
2. Уведомления: о брони и снятии брони — владельцу (вкл по умолчанию) и гостям (выкл по умолчанию), настраивается в «Настройках»; об удалении подарка — нет.
3. Старые `list_<id>`-ссылки закрыты, существующие гости сохранены.

Открыто: контакт поддержки для `/help`; что считать в аналитике (2.7).

## Критерии готовности к рекламе

- Посторонний не получает доступ по ID или поддельному webhook; личные экраны не появляются в группе.
- Одновременная бронь разными гостями даёт ровно одного победителя; повтор того же запроса не меняет состояние и не дублирует побочные эффекты; отмена ничего не публикует.
- Старые кнопки и удалённые объекты ведут к понятному выходу.
- Ручная проверка на iOS, Android и Desktop: отправка карточки, вход нового гостя через Start, длинные названия, крупный шрифт, пользователь без username.
- Несколько человек, незнакомых с ботом, проходят путь владельца и гостя без подсказок; точки, где они застряли, записаны.

## Отступления от исходного плана

- 0.2: токен — `has_secure_token` (24 символа base58), а не base64url; старые `list_<id>` пускают только тех, у кого доступ уже был; существующие гости сохранены.
- 0.1: регистрация webhook — в `.kamal/hooks/post-deploy`. После первого деплоя бот ~5 минут отвечал 401 (rake-задача не подключала gem); исправлено в #29, там же ошибки кнопок стали всплывающими окнами.
- 1.3: по решению пользователя уведомлений об удалении забронированного подарка нет. О бронях уведомляются владелец (по умолчанию вкл) и гости (по умолчанию выкл), каждый выбирает в «Настройках»; имя бронирующего не сообщается (#38).
